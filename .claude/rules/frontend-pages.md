# Frontend pages: UI behaviour

Page-level detail. The invariants these pages rely on (reconciliation, leaf-only, budget targets, averages window) are in `.claude/CLAUDE.md`. UI strings quoted here use ASCII apostrophes, like new code (older files still carry the typographic one).

## Text contrast
White cards, light theme: clickable text (row actions ＋ ✎ ✕, « Annuler », « ＋ objectif », Auto/Dissocier) is `text-zinc-600` with a `hover:text-zinc-900` hover (a delete ✕ hovers `hover:text-red-700`); secondary informative text (counts, Σ targets, badges, notes) is `text-zinc-500`. Never `zinc-400`/`zinc-300` for text a user reads or clicks (2.6:1 on white, below WCAG AA), SVG chart text included (`#71717a`, not `#a1a1aa`); the one left is the phone-only Sankey scroll hint. Green/red text (amounts, month-over-month deltas) is `text-green-700`/`text-red-700`: `green-600` is 3.2:1.

## Shared pieces
- Buttons: `.btn-primary` (filled, one main action per block) and `.btn-secondary` (bordered) in `globals.css`'s components layer, so a size utility on the element (`px-2 py-0.5 text-xs` for a compact row action) overrides the default size; never re-spell `bg-zinc-900 ... text-white`. Page title `<h1 className="text-xl font-semibold">`, section `<h2>` `font-semibold` at body size; month selects `px-2 py-1.5 text-sm`. The Nav underlines the current page (`/rapport` counts as « Le mois »).
- `lib/api.ts`: `ApiError` carries the `detail` strings (validation objects by their `msg`; a detail-less error gets `statusMessage(status)`, a failed fetch `UNREACHABLE`, both French); pages show `errorMessage(e)`, never `String(e)`, which prefixes an English "Error: ".
- Nav (`components/Nav.tsx`, entries in `lib/nav.ts::NAV_GROUPS`, one bar in three labelled groups: Analyser = Le mois, Budget, Statistiques; Traiter = Transactions, À classer, Catégories, Importer; Configurer = Réglages, Aide; `NAV` is the flat list the guide test uses; it must fit `max-w-5xl` on one line, hence `whitespace-nowrap` and tight gaps): « À classer » carries a count badge (amber while N > 0), N = `GET /api/transactions?uncategorized=true` `total`, and « Dernière opération : date » (the most recent value date, to see whether the statements are up to date) sits on the group-label row at the right, both refetched on every route change and on the `compta:uncategorized-changed` window event (`lib/api.ts::notifyUncategorizedChanged`, called by every categorising action).
- Account colours (`lib/accountColors.ts`, `components/AccountDot.tsx`, `lib/useAccounts.ts`): one of 8 named palette colours per account (`accounts.color`, names mirrored from `db.ACCOUNT_COLORS`, same order), else the palette entry at the account's position in the full `GET /api/accounts` list (sort_order order, external savings included, so never filter that list before looking a colour up; two accounts may share one, no uniqueness check). `AccountDot` is a decorative `bg-<colour>-500` dot (`aria-hidden`, the account label as tooltip) put before the account code in the Transactions rows (shown with `account_id`, falling back to the raw `account` string), the « À classer » tables (group operations, transfer candidates, rule conflicts), the dashboard tree's expanded operations and its imported-savings leaves (`node.synthetic` + `account_id`; an external-savings leaf has no `account_id`, so no dot). Not in the Import coverage table. The dot is colour only: the code always stays beside it, and the palette sits outside the text-contrast rules above.
- `CategoryPicker`: leaf-only typeahead (`lib/categorySearch` fuzzy search, ↑/↓ + Enter); hides group nodes (a top-level category without children is a leaf, and selectable).
- « Aide » page (`app/aide/page.tsx`): renders `docs/guide.md` (react-markdown + rehype-slug; the guide's `img/x.png` are served from `docs/img` by `app/aide/img/[name]/route.ts`). Each page's title carries a « ? » (`components/HelpLink`) linking to its heading, anchors in `lib/guide.ts` (`GUIDE_ANCHORS`, one per `lib/nav.ts` entry); the guide must not use relative links to files outside `docs/`, they break in the app.

## « Le mois » (`app/page.tsx`)
- One month only (no « Tous les mois »; the long view is Statistiques). The month lives in the URL (`/?month=YYYY-MM`, none for the latest month), handled by `lib/useMonthDashboard.ts` (shared with Budget: `pushState` + `popstate`, so Back returns to the previous month and a reload keeps it; an unknown month, the old `?month=all` included, falls back to the latest) with `components/MonthSelect.tsx` (also used by Statistiques with `withAll`); « Dernier mois » shows when another month is displayed; the report's « ← Le mois » link returns to the report's month.
- « Reste mois par mois » (`components/ResteTrend.tsx`, helpers in `lib/trend.ts`), from the payload's `history`: one bar per month, the displayed month in full colour, the latest budget month (still filling) outlined dashed, a partial month (`months_partial`) flagged « partiel » in the tooltip and in the month select, no legend, a tooltip with the month's Revenus/Dépenses/Épargne/Reste; on the dashboard a click switches to the month under the tooltip via the optional `onSelect`, the report passes none.
- « Détail par catégorie » (`TreeNode`): always shown, fully open. Each **leaf** lists its transactions (real leaves by `category_id`, the uncategorised bucket by the uncategorised filter, savings leaves by `account_id` or `libelle_match` via `?deposit_pattern=`), all loaded once per month by `lib/api.ts::listLeafOperations` (one `GET /api/transactions` per leaf from `report.ts::treeLeaves`, sent 6 at a time; the report uses the same helper); groups and the root just aggregate children inline.
- Budget summary (`components/BudgetGlance.tsx`, `lib/budget.ts::overrunCount`): one line under the Reste chart (actual / targets, groups over target, link to `/budget?month=`), hidden without targets.

## Budget (`app/budget/page.tsx`)
One month (same URL handling and select as « Le mois », no « Tous les mois »). `components/BudgetSection.tsx` (« Objectifs du mois », ok/warn/over colour bands in `lib/budget.ts`; also in the report's « Le mois en détail ») with `BudgetBalance` (margin = `income_reference` − Σ spending targets − savings goal, red when negative, a warning never a block; `lib/budget.ts::incomeReference`/`budgetMargin`/`categoryTargets`) atop the section and atop the Catégories page. Without any target the page points to Catégories.

## Money flow Sankey
`lib/moneyFlow.ts::moneyFlow` → `lib/flowLayout.ts::flowLayout` → `components/MoneyFlowChart.tsx`, plain SVG (no recharts `<Sankey>`: its layout can only relax nodes, which let the short income columns sink to the bottom, or top-align them).
- Graph: income source leaves → `Revenus` hub (skipped when a single source is all that comes in: it links straight to `Budget`) → central `Budget` → expense groups → leaves, plus an `Épargne` branch and a sign-aware balancing branch (`Reste` surplus right / `Découvert` deficit left).
- Values are gated **per leaf** and rolled up (an income source is a leaf with net credit, an expense a leaf with net debit), never the group net: income is mixed into expense groups (Salaire under Fixe), and the group net would hide expenses and make a Budget↔group cycle. `uncategorised` is shown gross on both sides (`Non classé`), so the income total matches `data.income`. The plug = `income − expenses − épargne` = the tree total = the Reste card.
- Expense leaves under 2.5% of total expenses fold into a per-group `Autres (<group>)`; a leaf name repeated under several groups gets its parent appended (`Prêt (Locatif)`).
- Layout: `flowLayout` keeps each column in the order `moneyFlow` emits (largest first, sub-groups before leaves, `Non classé`/`Épargne`/`Reste` last) and stacks bands in the order of their other end, so links don't cross; keep that order when changing `moneyFlow`. Centring, link tints by `role`, labels, tooltip and height live in `flowLayout.ts` and `MoneyFlowChart`.

## Statistiques (`app/statistiques/page.tsx`)
Hosts only « Moyennes mensuelles » for now (moved off the dashboard). The only page with « Tous les mois »: a `MonthSelect` `withAll` (+ each month, partial ones flagged; local state, not in the URL) loads `GET /api/dashboard?month=` and passes it to `AveragesSection`.

## « Moyennes mensuelles » table (`components/AveragesSection.tsx`, `lib/averages.ts`)
Own fetch (`GET /api/dashboard/averages`), so switching the period doesn't refetch the page's dashboard payload (the window skips the latest month and the partial ones, so it can hold fewer months than asked); the period resets to 12 months on reload. One **signed** column per row (`averageNet`/`monthNet`: income − spending, so the offset cancels out) + « Écart » + « Objectif »: categories, `Non classé` and a `Total` row (= Revenus − Dépenses), then a separate « Comptes d'épargne » block (one row per account, « Mis de côté / mois », positive = saved). The month column shows the displayed month's value with its gap (month − average) in parentheses, always grey; the colour sits on the « Objectif » cell of an own target only (`ownTarget`): green under 90 % of it, amber 90-100 %, red over, judged on the displayed month's spending (the average in « Tous les mois », where the gaps are hidden).

## Printable report (`/rapport`, `app/rapport/page.tsx`, `lib/report.ts`)
- Code layout: `page.tsx` loads the data and lays the sheets out (`Report`); `Sheet`, `ReportStat`, `StatementTable`, `BreakdownTable`, `MonthDetail` and `TreeRows` sit beside it, with the shared cell/highlight styles in `tableStyles.ts`.
- Dashboard link « Rapport PDF » (`reportLink`). A4 pages (`.sheet` / `.sheet-landscape` + `@page` in `globals.css`, previewed on screen at print width; nav and toolbar `print:hidden`) saved through the browser's print dialog (`window.print()`, the page title names the PDF), no PDF library.
- Frontend-only: `GET /api/dashboard?month=M` + `GET /api/dashboard/averages?months=12&month=X` per statement month (the window is the latest 12 complete months whatever M, so each call's `month_*` values make one column and an older M is still compared with the latest average). M defaults to the latest **complete** budget month.
- **Net of refunds** (`netOfRefunds`): the averages' `offset` is taken off both Revenus and Dépenses (cards, sentence, statement totals), so each category is net, rows add up to the totals and the Reste is unchanged; its Revenus/Dépenses can be lower than the dashboard's, as « Comment lire » says.
- Pages: synthèse (sentence, the four cards with their 12-month average and gap, `ResteTrend`, a « Comment lire » box that also explains the tables); « Les derniers mois » (6 months + average, rows striped: income by income-side leaf, spending by top-level category, savings by account, Non classé on both sides; totals = `history` net of that month's offset); « Le mois en détail » (« Dépenses par catégorie » / « Revenus par catégorie » per group/leaf with bars (`breakdown`), then `BudgetSection`); « Détail par catégorie » (the balance tree fully open, total = Reste, each leaf listing its operations: one `GET /api/transactions` per leaf (`treeLeaves`) with the drill-down's filters, `lib/api.ts::leafFilters`); the Sankey on a landscape page.
- A notable report-month amount is bold red/green in every table (`notable`: over its own target, or ≥ 20 € and ≥ 20 % from its average, toned by `gapTone`); no separate attention list. The app tracks flows, not balances: the report has none.

## Transactions page (`app/transactions/page.tsx`)
- Code layout: `page.tsx` owns the loading, the filters' state, the editor/rule-form state, the live preview and the transfer actions; `Filters`, `SelectionBar`, `TransactionRow` (one line, the editor passed in as its `editor` node) and `CategoryEditor` sit beside it and only render.
- Filters (`Filters`): « Sans catégorie uniquement », a month select and an account select (« Tous les comptes » + `GET /api/accounts` minus the external savings accounts, which have no rows of their own; `?account=` on the list), all combined; « Exporter CSV » carries the same month, account and uncategorised filters.
- One inline categorisation editor per row (button-confirmed, never instant-on-select): pick a leaf, then **either** « Cette opération » (manual: `PATCH /api/transactions/{id}` `{category_id, note}`) **or** « Règle (opérations similaires) » (`POST /api/rules`, with a live debounced match-count preview reusing `?libelle_contains=&uncategorized=true`; `suggestPattern` prefills the pattern by stripping a dated prefix). The description is the `note` in manual mode, the rule's `description` in rule mode. Available whether or not « Sans catégorie uniquement » is on. In manual mode « Scinder » opens a 2nd part (amount in euros + a `CategoryPicker`; `SplitForm` state on the page, sent as `split_category_id`/`split_amount` together with `category_id`, since a `category_id` drops the split server-side; « Annuler le split » closes it, then Valider keeps only the 1st category); the row shows « Courses + Maison ». Not offered in « À classer » nor the bulk PATCH. Rule form state: `lib/ruleForm.ts`, shared with the Catégories rule editor. In rule mode an account select (`components/AccountSelect.tsx`, « Tous les comptes » by default, loads the accounts itself, external savings left out) limits the rule to one account and the match count to that account's rows; the Catégories rule editor (`RuleEditor`, a `RuleRow` badge shows the account code) and the « À classer » group editor (`Draft.account_id`, passed to `previewRule`; the select keeps its own arrow keys) use the same select.
- ⚙ rule / ✎ manual provenance badges; transfer rows show a "⇄ virement" tag instead of a picker, with Dissocier / Auto; ticking up to 2 rows offers « Associer en virement » / « Marquer comme virement ».
- « Exporter CSV » (`GET /api/transactions/export`, `lib/api.ts::transactionsExportUrl`): every row matching the filters, oldest first, for a French Excel (French headers, dd/mm/yyyy, comma decimals, full category path), unlike the config CSVs.

## « À classer » page (`app/a-classer/page.tsx`, `lib/triage.ts`)
- Code layout: `page.tsx` owns the groups, the draft, the keyboard handler (`onKeyDown`), `act`/`submit`/`pair`/undo and the toast; `Shortcuts`, `GroupSummary`, `GroupEditor` (also exports `Draft`), `TransferCandidates` and `OperationsTable` sit beside it and only render.
- « Conflit de règles » (`RuleConflicts.tsx`, `GET /api/transactions/rule-conflicts`, loaded with the groups): first on the page, one row per operation matched by rules of different categories, with a `CategoryPicker` to class it by hand (`PATCH`, « Annuler » = `category_id: null`, back to a conflict) and each rule in cause linking to `/categories?q=<pattern>` (`lib/triage.ts::ruleLink`; the Catégories page reads `?q=` once into its search box, `queryFromSearch`). No delete or disable button here. The rule preview line (`previewMessage`) appends « N opérations correspondent aussi à la règle X (catégorie Y) » when the rule would create a conflict; the same message (`conflictsMessage`) follows a saved rule in the « À classer » toast, the Transactions flash and a Catégories warning banner.
- A group of 2+ defaults to a rule, a lone operation or a generic pattern to a manual assignment (`defaultMode`). Manual mode uses the bulk `PATCH /api/transactions` `{ids, category_id, note}`. « Annuler » (8 s, or Alt+Z) deletes the created rule or clears the batch.
- The active group lists its `transfer_candidates` under « Virement interne ? » with « Associer en virement » (`POST /api/transactions/transfer-pair`; « Annuler » = `PUT /api/transactions/{id}/transfer` `auto`). A group with other operations stays active after a pairing.
- Keyboard: the active group's category search keeps the focus; ↑/↓ move between groups (or through the results while a query is typed), Enter classes in the highlighted result else the suggestion, Alt+M toggles rule/manual, →/← show/hide the operations, Échap clears the query then the draft; the next group becomes active after a validation.

## Catégories page (`app/categories/page.tsx`, `lib/categoryTree.ts`)
- Code layout: `page.tsx` owns the loading, `run`/`act`/undo, search, selection and the move; `CategoryRow` (one tree line: rename / re-parent via `reparentOptions`, add child, delete; `CategoryTarget` for the target), `LeafContents` (a leaf's rules and manual operations, driven by the page's `LeafActions`), `RuleRow`, `ManualRow`, `RuleEditor`, `RuleOperations`, `Net` sit beside it. Inline-edit state (rename, target, rule, note, add form) lives in each row, not on the page, so several rows can be in edit at once; the selection and the open rules stay on the page because they outlive a collapsed leaf.
- The tree: ＋ sub-category, ✎ rename / re-parent, ✕ delete, inline budget target on a leaf or a group (a group with targeted sub-categories shows their Σ, a category under a targeted one offers none). Each node shows what classifies operations into it (rules, their operations, manual assignments; a group sums its leaves) and its signed monthly average over the last 12 complete months (`GET /api/dashboard/averages?months=12&month=all`, `averageNets`; a rule row still shows its operations' total).
- A leaf expands (▸) into « Règles » (⚙, `GET /api/rules`, `RuleOut` carries `operation_count`/`debit`/`credit`; inline edit, delete, « ＋ règle »; a rule expands to its operations, `GET /api/transactions?rule_id=`, 20 per page) and « Opérations classées à la main » (✎ note edit, ✕ clears = `{category_id: null, note: null}`; loaded with `?manual=true`, 1000 per page).
- Ticked rules and manual operations move together to a leaf: `POST /api/categories/{id}/move` `{rule_ids, transaction_ids}` (204; 404 unknown category or id, 422 on a group, nothing to move or a non-manual operation; all checked before anything moves; one `apply_rules` when rules moved). A rule takes all its operations; a manual operation keeps its note. A rule-classified operation can't move alone: « Classer à part » = `PATCH /api/transactions/{id}` `{category_id}` (it becomes manual). « Annuler » (8 s, Alt+Z) replays the move back (`undoMoves`) or clears the class-aside (its rule takes it back).
- A split operation is listed under both its categories (`heldBy`), each time with that leaf's part (`partInLeaf`) and « scindée, sur N € » (`ManualRow` gets `leafId`); moving or clearing it acts on the whole operation and drops the split (an undo of the move restores the category, not the split).
- Search (accents and case folded) on category names, rule patterns / descriptions and manual libellés / notes: opens the leaves holding a match and shows only matching items (a node matched by name shows everything below it).
- Subdividing a populated leaf hands its rules and operations to its first child (`create_category`), to be redistributed here; its target stays on it. The config CSVs are written from Réglages « Sauvegarde », not from this page.

## Réglages (`app/settings/page.tsx`)
One `<h1>` « Réglages » with a sticky table of contents (anchors to `#comptes`, `#virements-internes`, `#virements-manuels`, `#sauvegarde`): « Comptes » (`AccountsSection`: the accounts table (with the « Départ » column) + one form to add or edit, code and type disabled when editing, a start date for checking accounts, a colour picked among the palette swatches or « Par défaut » = none; the table shows the dot before each code; `PUT /api/accounts/{code}`, which re-derives the transfers), transfer markers, « Virements manuels » (`?manual_transfer=true` rows grouped into pairs by `lib/manualTransfers.ts::groupManualTransfers`, each with an Auto action), « Sauvegarde » (« Enregistrer la configuration » and the separate « Exporter les opérations en CSV », `POST /api/config/export-statements`, each with its own result message). A failed action's error shows in its own section (`SectionError`, sticky below the table of contents while that section is on screen).
